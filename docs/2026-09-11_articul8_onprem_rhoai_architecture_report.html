추정의 상세 근거:
1. 컴팩트 클러스터 집약 타당성: AWS 실측 22대 노드/316개 파드는 대부분 0.2~0.5 Core 수준의 소형 마이크로서비스였습니다. R770 3대의 총 192코어/768GB 메모리는 316개 파드를 여유 있게 집약 수용(Consolidation)할 수 있습니다.

🔍 AWS 대비 RHOAI(On-Prem) 설치 시 사전 파악 필요 자료

AWS EKS 환경은 완전관리형 서비스(RDS, ElastiCache, S3, ALB, IAM)가 지원되었으나, 온프레미스 RHOAI에 배포하려면 아래 7대 영역의 기술 자료 및 제조사 사양이 사전에 반드시 확인되어야 합니다.

영역 사전 파악 및 검토 필요 항목 파악 목적 및 온프레미스 영향도
1. Articul8 공식 온프레미스 스펙 • a8 CLI의 온프레미스 provider 지원 여부 (`provider: onprem` 또는 `openshift`)
• Terraform 생략 플래그(`--skip-terraform`) 시 온프레미스용 Helm Chart 및 mustache 템플릿 제공 여부		 AWS IaC 코드를 우회하고 순수 쿠버네티스/OpenShift 매니페스트로 배포 가능한지 확인 필수.
2. 폐쇄망 오프라인 패키징 • 98개 컨테이너 이미지의 오프라인 Tarball 및 SHA-256 체크섬
• 모델 가중치(Weights) 파일 직접 다운로드 URL 또는 번들
• 외부 ECR 인증 토큰 종속성 제거 방안 (과거 403 오류 차단)		 인터넷이 차단된 사내망에서 Articul8 Hub 인증 없이 로컬 레지스트리로 배포할 수 있는 유일한 경로.
3. S3 오브젝트 스토리지 요구 규격 • 10개 S3 버킷(ModelMesh, VectorDB, Flyte, Loki 등)의 API 호환성
• MinIO / ODF NooBaa 사용 시 Presigned URL 및 Multipart 업로드 지원 여부		 AWS S3 버킷 10개를 사내 오브젝트 스토리지로 100% 매핑하기 위한 사전 검증.
4. 인-클러스터 DB 사양 • PostgreSQL 요구 버전(14/15/16) 및 필수 Extension (pgvector, pg_trgm 등)
• Redis Sentinel 클러스터링 및 암호화/비밀번호 주입 형식		 AWS RDS와 ElastiCache를 대체할 CloudNativePG 및 Redis Operator의 배포 스펙 확정.
5. GPU 드라이버 & RHOAI 서빙 • Red Hat Enterprise Linux CoreOS(RHCOS)와 NVIDIA H200 NVL 드라이버 호환성
• RHOAI KServe/vLLM과 Articul8 ModelMesh 간의 인터페이스 연동 방식		 GPU 가속기가 KServe 및 A8 모델 관리자에 정상 노출되어 대형 모델이 구동되도록 보장.
6. 네트워크 인그레스 & 도메인 • 사내 사설 FQDN(예: `a8.internal.company.com`) 등록 및 DNS 연동
• OpenShift Route(HAProxy) TLS Edge Termination 및 사내 사설 Root CA 배포		 인터넷 공개 ALB 대신 사내 인트라넷 보안망 안에서 웹 UI와 API를 안전하게 서비스하기 위함.
7. 지식 그래프 백업 체계 • ArangoDB Enterprise 핫백업 명령(`--upload`) 시 온프레미스 S3 엔드포인트 지원 여부 AWS S3가 없는 환경에서 클러스터 장애 시 지식 그래프 영구 보존을 위한 필수 조건.

AWS 설정 항목 AWS 환경 동작 RHOAI / 온프레미스 대체 기술 구체적 대체 구현 방식
provider.aws.account / region AWS 계정 및 리전 태깅 사내 테넌트 ID & Node Topology 계정 필드 제거, topology.kubernetes.io/zone: dc1-rack1 라벨 적용
eks.model_inference_large_group_instance_type AWS P4de VM 자동 프로비저닝 RHOAI AcceleratorProfile + NodeSelector nodeSelector: node-role.kubernetes.io/gpu: "" 및 H200 4장 직접 할당
loadBalancer.scheme: internet-facing AWS ALB 생성 (megazone.articul8.ai) OpenShift Route / MetalLB OpenShift HAProxy Ingress Route (Edge TLS) 생성 및 사내 L4 VIP 할당
StorageClass: ebs-sc (gp3) AWS EBS 볼륨 동적 생성 (47개 PVC) OpenShift Data Foundation (ODF) ocs-storagecluster-ceph-rbd (블록) 및 cephfs (공유 볼륨)로 매핑
AWS S3 Buckets (10개) 비정형 데이터, 모델, 로그 저장 MinIO Enterprise 또는 ODF NooBaa 인-클러스터 MinIO S3 호환 엔드포인트 주입 및 ObjectBucketClaim(OBC) 활용
AWS RDS & ElastiCache 완전관리형 PostgreSQL 및 Redis CloudNativePG & Redis Operator 오픈소스 Operator 기반 3노드 HA 클러스터를 OpenShift 내에 직접 배포
AWS IAM / IRSA / Pod Identity AWS 리소스 접근 임시 토큰 발급 HashiCorp Vault + External Secrets External Secrets Operator의 백엔드를 사내 HashiCorp Vault로 지정

🚀 On-Premise RHOAI 배포 절차 가이드 (Playbook)

하드웨어 도입부터 OpenShift 설치, RHOAI 가속기 활성화, Articul8 배포 및 검증까지의 6단계 표준 이행 절차입니다.

Step 1. 하드웨어 및 OS 부트스트래핑

• Bastion(R570)에 RHEL 9 설치 및 네트워크 본딩(25GbE LACP).
• iDRAC10을 통한 R770/XE7740 BIOS 최적화 및 고정 IP/DNS 설정.

Step 2. OpenShift Compact 클러스터 설치

• OpenShift 4.16+ IPI/UPI로 R770 3대를 Compact HA 클러스터로 구성.
• XE7740을 별도 GPU 전용 워커 노드로 클러스터에 조인.

Step 3. 인프라 Operator 및 스토리지 구성

• ODF(Ceph) 또는 LSO 배포 → ocs-storagecluster-ceph-rbd 생성.
• MinIO 배포(10개 S3 버킷), CloudNativePG(PostgreSQL), Redis Operator 배포.

Step 4. RHOAI 및 NVIDIA 가속기 배포

• Red Hat OpenShift AI Operator 및 Node Feature Discovery(NFD) 설치.
• NVIDIA GPU Operator 설치 후 H200 NVL 4장 드라이버 인식 검증.

Step 5. 오프라인 이미지 미러링 & Articul8 설치

• Bastion에서 폐쇄망 레지스트리로 98개 이미지 푸시.
• ./a8 configure -c a8-onprem.yaml 실행 후
• ./a8 install -c a8-onprem.yaml --skip-terraform 실행.

Step 6. 수용 검사 및 스모크 테스트

• ./a8 healthcheck로 38개 Helm 릴리스 정상 동기화 확인.
• ./a8 smoketest -c a8-onprem.yaml로 LLM 추론 및 Warp 쿼리 검증.

⚠️
치명적 위험 방지 (ECR 403 재발 방지): 과거 AWS 환경에서 발생했던 "공급사 ECR 403 Forbidden" 장애는 온프레미스 구축 시 반드시 사전에 공급사로부터 오프라인 컨테이너 이미지 Tarball 패키지를 인계받아 사내 프라이빗 레지스트리에 푸시해 두어야 100% 예방할 수 있습니다.
