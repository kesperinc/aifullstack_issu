## 1. 제안 배경 및 필요성

### 1.1 KGM BOM(Bill of Materials) 업무의 현주소 및 과제
- **복잡한 차종·사양 체계**: 토레스(EVX/하이브리드/가솔린), 렉스턴(뉴 아레나/스포츠 칸), 액티언, 코란도, 티볼리 등 KGM 라인업 확대에 따라 차종·트림·엔진·구동방식별 수십만 개 부품 BOM 데이터의 복잡도 급증.
- **연구개발(R&D) 및 현업의 정보 탐색 병목**:
  - 연구원, 설계자, 상품기획, 원가기획 부서에서 과거 차종 사양 비교, 부품 공용화 여부 확인, 특정 옵션 조합별 부품 번호 확인 시 레거시 시스템(PLM/ERP)의 복잡한 화면과 파편화된 테이블 구조로 인해 탐색에 과도한 시간(건당 20~30분 이상) 소모.
  - IT 부서(KG ICT)로의 비정형 데이터 추출 및 Ad-hoc 쿼리 요청이 집중되어 업무 부하 가중.
- **데이터 준비 및 정제 단계의 필수성**:
  - 과거 타사 프로젝트의 경우 사전에 데이터셋이 이미 정제되어 있던 특수 케이스였습니다. 실무 프로덕션 적용을 위해서는 **KGM 현업과 IT(KG ICT) 간의 상호 데이터 스키마 정의, 부품 코드 표준화, 레거시 정합성 검증 등 체계적인 데이터 준비(Data Readiness) 단계가 필수적으로 선행**되어야 합니다.
- **On-Premise 및 Public Cloud 유연성 요구**:
  - 차량 설계 사양 및 BOM 정보의 보안 수준에 따라 고객사(KGM/KG ICT)가 사내 전산실 내 완전 격리형 **On-Premise**를 선택하거나, 유연한 확장을 위한 **Public Cloud**를 채택할 수 있습니다. 따라서 특정 인프라나 상용 솔루션에 종속되지 않고 양쪽 환경을 모두 수용할 수 있는 표준 하이브리드 아키텍처가 필수적입니다.

### 2.3 원천 BOM DB 연동 및 지속적 RAG 현행화(Continuous RAG) 설계

부품 데이터는 매주/매월 설계 변경(ECO/EO) 및 신규 연식 변경에 따라 지속적으로 업데이트되므로, 시스템이 최신 상태를 스스로 유지하도록 설계합니다.

1. **원천 BOM DB 무부하 연동 (Read-Only Replica & CDC)**:
   - 본 챗봇 시스템은 KGM 운영계(PLM/ERP) DB에 부하를 주지 않기 위해 **읽기 전용 복제본(Read Replica)** 또는 컬럼형 스냅샷을 주기적으로(예: 매일 자정 또는 실시간 CDC) 동기화합니다.
2. **자주 질문하는 내용(FAQ)의 시맨틱 캐싱**:
   - 현업 연구원들이 반복적으로 묻는 주요 질문(예: *"토레스 하이브리드 엔진오일 규격 및 필터 품번"*, *"렉스턴 4WD 트랜스퍼 케이스 적용 부품"*)은 질문-답변 페어로 시맨틱 캐시(Semantic Cache)에 저장되어, **LLM 재추론 없이 0.1초 내 즉시 응답**하여 GPU 리소스를 대폭 절약합니다.
3. **최신 출시 차종 및 설계 변경점의 Active Knowledge RAG 현행화**:
   - 신규 차종이나 신규 옵션 패키지가 등록되면, 자동화 배치 파이프라인이 메타데이터와 사양 설명서를 자동으로 벡터화하여 **Active RAG 지식 저장소**에 즉각 반영합니다.
4. **피드백 DB 기반 지속적 모델 튜닝**:
   - 현업의 '좋아요/정정' 피드백을 축적하고 이를 동적 예제(Dynamic Few-shot) 프롬프트와 향후 경량 모델 미세조정(Fine-tuning) 데이터셋으로 재활용합니다.

## 3. 모델 및 서빙 혁신: 초경량화 코딩 특화 모델 & 고속 추론 서빙 아키텍처

### 3.1 모델 압축·경량화 기술 기반 초저지연 코딩 특화 모델(sLLM)
- **도입 배경**:
  - 자동차 BOM 및 사양 질의는 정확한 분석 코드 생성과 지연 없는 빠른 응답 속도가 핵심입니다.
  - 본 제안에서는 모델 경량화 파이프라인을 통해 **구조적 프루닝(Pruning), FP8/INT4 정밀 양자화(Quantization), 도메인 지식 증류(Knowledge Distillation)**를 거친 **초경량 코딩 특화 오픈소스 모델(sLLM)**을 탑재합니다.
- **성능 이점**:
  - 모델 크기와 GPU 메모리(VRAM) 점유율을 기존 대비 40~50% 이상 절감하면서도 코딩/추론 정합성을 95% 이상 보존합니다.
  - 듀얼 GPU 서버(총 96GB급 VRAM) 환경에서 현업 동시 접속자 처리량(Concurrency)을 2배 이상 확대합니다.

### 3.2 엔터프라이즈 초경량 고속 추론 서빙 엔진 구성
단일 사용자 개발 도구 수준의 기본 서빙 방식은 엔터프라이즈 환경에서의 동시 요청 처리 및 다단계 에이전트 캐싱에 한계가 있습니다. 이에 따라 다음 3가지 방식의 초고속 서빙 아키텍처를 환경에 맞게 구성합니다:

| 서빙 엔진 유형 | 기술적 특징 및 장점 | KGM 사업 적용 가치 및 추천 시나리오 |
| :--- | :--- | :--- |
| **프리픽스 캐시 재사용 기반<br>에이전트 특화 서빙 엔진** *(최우선 권장)* | • 트리 기반 Attention KV 캐시 재사용 극대화<br>• 다단계 에이전트 프롬프트 및 샌드박스 반복 호출 시 추론 지연시간 70% 단축<br>• 초당 토큰 처리량(TPS) 기존 대비 1.5~2배 이상 향상 | **복잡한 다단계 Coding Agent 실행에 최적**<br>(샌드박스 자가수정 루프 동작 시 압도적 응답 속도 제공) |
| **메모리 페이지 최적화 기반<br>엔터프라이즈 배치 서빙 엔진** *(표준)* | • 가상 메모리 페이징 알고리즘 기반 GPU 메모리 파편화 제로 달성<br>• 컨테이너 AI 플랫폼 표준 서빙 컨트롤러와 네이티브 연동 및 오토스케일링 지원 | **엔터프라이즈 표준 클러스터 기반 대규모 운영 안정성 보장** |
| **C/C++ 네이티브 기반<br>초경량 제로 디펜던시 런타임** *(경량)* | • 무거운 프레임워크 종속성 없는 순수 C/C++ 초경량 실행 바이너리<br>• 극소 메모리 풋프린트 및 CPU/GPU 하이브리드 오프로딩 지원 | **자원 제약 환경 또는 개발·검증용 로컬 인스턴스에 최적** |

## 4. 데이터 엔진 혁신: 임베디드 OLAP + 임베디드 Graph DB 듀얼 아키텍처

자동차 BOM 데이터는 단순한 표 형태의 집계뿐만 아니라, **부품 간의 복잡한 계층 관계(Hierarchical Tree: 모듈 ➔ 서브어셈블리 ➔ 단품)**와 **부품 공용화/대체 관계(Dependency Graph)**를 지니고 있습니다.  
따라서 본 제안에서는 **인프로세스 임베디드 OLAP 엔진(수치 집계 및 Diff 연산)**에 **인프로세스 임베디드 Graph DB(계층 트리 순회)**를 결합한 **듀얼 임베디드 데이터 아키텍처**를 구축합니다.

```
┌───────────────────────────────────────────────────────────────────┐
│        Dual Embedded In-Memory Data Layer (Zero-Copy)             │
├─────────────────────────────────┬─────────────────────────────────┤
│  • 임베디드 OLAP 엔진           │  • 임베디드 Graph DB            │
│    - 컬럼형 고속 수치 집계      │    - BOM 다계층 트리 재귀 순회  │
│    - 트림/사양 간 차이(Diff) 연산│    - 부품 종속성 / 대체품 경로  │
├─────────────────────────────────┴─────────────────────────────────┤
│    ▲ 공유 메모리 기반 제로카피(Zero-Copy) 데이터 파이프라인 결합   │
└───────────────────────────────────────────────────────────────────┘
```

1. **임베디드 OLAP 엔진의 압도적 집계 속도**: 별도의 외부 DB 서버 통신 오버헤드 없이 샌드박스 프로세스 내에서 수백만 건 부품 테이블을 컬럼 기반 벡터화 연산으로 수 밀리초 내 집계·필터링하며, 사양 간 차이점(Diff)을 즉각 산출합니다.
2. **임베디드 Graph DB의 초고속 트리 순회**: 무거운 분산 그래프 서버를 별도로 구축하지 않고도 프로세스 내에 직접 내장되어, 그래프 쿼리를 통해 완성차-모듈-어셈블리-단품 간 다계층 트리와 상위 적용 차종 역추적(Where-Used)을 밀리초 단위로 수행합니다.
3. **공유 메모리 Zero-Copy 결합 시너지**: 그래프 순회 결과와 수치 집계 테이블을 메모리 복사 없이 단일 프로세스에서 결합하여 복합 질의를 초고속으로 처리합니다.

## 5. 인터페이스 혁신: 음성 검색(Voice-to-BOM) & 계층적 드릴다운 트리 UI

1. **음성 검색 (Voice-to-BOM / 온프레미스 신경망 STT)**:
   - 연구소 실험실이나 조립·정비 현장에서 장갑을 끼고 작업 중에도 마이크 음성 질의를 통해 핸즈프리로 부품 정보를 호출할 수 있습니다.
   - 외부 클라우드 전송 없이 사내망 GPU 서버에 배치된 온프레미스 음성 인식(STT) 모델을 통해 한국어 및 자동차 부품 전문 약어를 고속 변환합니다.
2. **계층적 드릴다운 트리 인터페이스 (Hierarchical Drill-down Navigator)**:
   - 완성차 ➔ 시스템(샤시/바디/전장) ➔ 메인 모듈 ➔ 서브어셈블리 ➔ 단품 파트로 이어지는 자동차 BOM 구조를 시각적 트리 다이어그램으로 제공합니다.
   - 챗봇 답변에서 특정 모듈을 클릭하면 해당 하위 부품 트리가 동적으로 펼쳐지며, 사용자가 자연어 대화와 마우스 클릭을 혼합하여 양방향으로 탐색할 수 있습니다.

## 8. 전체 핵심 용어집 (Glossary)

| 용어 (Term) | 영문 / 분류 | 상세 정의 및 본 사업에서의 역할 |
| :--- | :--- | :--- |
| **BOM / EBOM / MBOM** | Bill of Materials | 자동차 한 대를 구성하는 전체 부품의 계층 관계 데이터베이스 (연구소 설계 EBOM / 생산 공정 MBOM). |
| **표준 컨테이너 AI 플랫폼** | Enterprise Kubernetes AI Platform | 쿠버네티스 기반 엔터프라이즈 AI 표준 플랫폼으로, On-Premise와 Public Cloud 간 완벽한 이식성과 확장성을 보장하는 기반 스택. |
| **모델 경량화 (Model Compression)** | Pruning & Quantization | 구조적 프루닝, INT4/FP8 정밀 양자화, 지식 증류를 통해 코딩 특화 모델의 VRAM 사용량을 절반으로 줄이고 추론 속도를 극대화하는 기술. |
| **초고속 추론 서빙 엔진** | High-Speed LLM Serving Engine | 프리픽스 KV 캐시 재사용 및 메모리 페이지 최적화를 통해 다단계 에이전트 반복 추론 지연을 70% 이상 단축하는 서빙 런타임. |
| **임베디드 OLAP 엔진** | In-Process Analytical Engine | 별도 DB 서버 없이 샌드박스 프로세스 내에 내장되어 수백만 건 BOM 데이터를 수 밀리초 내 집계·Diff 연산하는 컬럼형 분석 엔진. |
| **임베디드 Graph DB** | In-Process Graph Database | 샌드박스 프로세스 내에 직접 내장되는 초경량 그래프 데이터베이스로, BOM 다계층 트리 순회 및 부품 종속성·대체 경로 탐색에 최적화. |
| **Continuous RAG** | 지속적 RAG 현행화 | 원천 BOM DB 무부하 동기화(Read Replica/CDC) 및 신규 차종, 부품 변경점(ECO), 빈출 FAQ를 자동 인덱싱하는 파이프라인. |
| **Semantic Cache** | 시맨틱 캐시 | 자주 묻는 질문(FAQ)의 의미적 유사도를 판별하여 LLM 재추론 없이 0.1초 내 즉각 응답을 반환하는 고속 인메모리 캐시. |
| **Code-Interpreter Agent** | Sandbox Coding Agent | LLM이 분석 코드(Python/OLAP/Graph 쿼리)를 직접 작성하고 보안 격리 샌드박스에서 실행하여 정확한 결과를 도출하는 에이전트. |
| **Self-Correction Loop** | 자가 수정 루프 | 코드 실행 에러나 빈 결과 발생 시 에이전트가 에러 스택을 스스로 해석하여 자체 디버깅·재실행함으로써 정합성 90%+를 보장하는 메커니즘. |
| **Voice-to-BOM** | 온프렘 음성 검색 인터페이스 | 연구원/현장 실무자가 마이크 음성 질의 시 온프레미스 신경망 STT 모델을 통해 즉시 부품 검색을 수행하는 핸즈프리 기능. |
| **Drill-down Tree UI** | 계층적 드릴다운 트리 UI | 완성차부터 단품 부품까지 이어지는 BOM 계층 트리를 시각적으로 펼쳐가며 대화와 클릭을 결합 탐색하는 인터페이스. |
| **Data Readiness** | 상호 데이터 준비성 | AI 착수 전 고객사와 수행사 간 원천 BOM 스키마 정의, 부품 코드 표준화, 테이블 정제를 수행하는 필수 선행 작업 단계. |

## 9. 제언 및 사전 협의 요청 사항

1. **인프라 구축 형태 결정 (On-Premise vs Public Cloud)**:
   - 사내 전산실 내 전용 GPU 서버 신규 도입(**Option A**) 또는 기보유 인프라/클라우드 활용 SW 구축(**Option B**) 방향성 확정
2. **원천 BOM DB 접근 및 복제 파이프라인 협의**:
   - 운영계 영향도를 배제하기 위한 읽기 전용 복제본(Read Replica) 및 배치 연동 방안 협의
3. **상호 데이터 준비(Data Readiness) 협의체 구성**:
   - 1차 파일럿 대상 대표 차종(토레스, 렉스턴, 액티언 등)의 원천 스키마 정의 및 도메인 정제를 수행할 공동 실무진 지정
