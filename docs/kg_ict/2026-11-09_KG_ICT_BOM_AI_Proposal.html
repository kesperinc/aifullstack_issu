Technology Paradigm

2. 2026 차세대 기술 차별화: 왜 Coding Agent인가?

과거의 Text-to-SQL 방식은 단 한 번의 SQL 문법 생성으로 끝나기 때문에 복잡한 테이블 조인 오류나 빈 결과(Empty Result) 발생 시 대응이 불가능했습니다. 반면 2026년 차세대 패러다임인 'Code-Interpreter Agent'는 경량화 코딩 특화 모델이 분석 코드를 작성하고 사내 격리 샌드박스에서 즉시 실행 및 자가 수정을 수행하여 현업의 복합 분석 요구를 완벽히 해결합니다.

과거 Text-to-SQL 방식의 한계

  • 단발성 생성(Single-shot)의 취약성: 문법 오류 또는 빈 데이터 발생 시 즉각 실패 응답 반환
  • 복잡한 BOM 계층 구조 해석 불가: 수백 개 컬럼과 트리 구조를 SQL 단일 쿼리로 표현하는 데 구조적 한계
  • 사양 비교(Diff) 및 복잡 연산 불가: 단순 조회를 넘어선 트림 간 부품 차이점 계산, 수식 연산 불가능
  • 사전 정의된 고정 Intent 종속: 5개 인텐트 외의 현업 자유 질문에 대해 오분류 다수 발생

차세대 Sandbox Code-Interpreter 혁신

  • 실행 및 자가 수정 (Self-Correction Loop): 분석 코드와 임베디드 DB 쿼리를 샌드박스에서 실행 후 오류 발생 시 스스로 디버깅하여 90%+ 정합성 확보
  • 강력한 프로그래밍 언어 표현력: 계층 트리 재귀 탐색, 인메모리 데이터프레임 가공, 정밀 사양 Diff 완벽 처리
  • 자유도 높은 복합 질문 처리: "토레스와 렉스턴의 서스펜션 부품 차이와 단종 여부" 등 고난이도 복합 질의 즉각 해결
  • 100% 온프레미스 경량화 코딩 모델: 모델 경량화 솔루션을 거친 코딩 특화 모델을 통해 사내 GPU 서버에서 기밀 데이터를 안전하게 격리 구동
End-to-End Architecture

3. 차세대 엔드투엔드 시스템 아키텍처 및 6단계 처리 프로세스

사용자의 음성/텍스트 질의가 유입되어 최종 답변과 계층 트리 UI로 반환되기까지의 6단계 엔드투엔드 처리 흐름과, 이를 뒷받침하는 5대 기능 블록 및 인프라 인스턴스 연동 구조, 그리고 원천 BOM DB 무부하 동기화 및 지속적 RAG 현행화(Continuous RAG)를 정의합니다.

3.1 6단계 엔드투엔드 질의-응답 처리 프로세스

STEP 01
사용자 쿼리 유입
웹 포털 텍스트 또는 마이크 음성 질의 (Voice-to-BOM, 온프렘 음성인식 STT 변환)
STEP 02
의미해석 LLM
시맨틱 캐시(FAQ) 확인 후, 신규 질의 의도(Intent) 분석 및 차종/부품코드 엔티티 추출
STEP 03
쿼리/코드 변환 LLM
경량화 코딩 특화 모델이 임베디드 DB 쿼리, 그래프 탐색 쿼리, Diff 연산 분석 코드 동적 작성
STEP 04
격리 샌드박스 탐색
보안 격리 컨테이너에서 임베디드 DB 수치 집계 및 임베디드 그래프 DB 트리 순회 (Self-Correction 탑재)
STEP 05
답변 작성 (합성)
결과 데이터프레임 기반 부품 비교표 렌더링, 사양 차이점 요약 및 스프레드시트 다운로드 생성
STEP 06
멀티모달 최종 응답
대화창 표출, BOM 계층 트리 뷰 동적 확장, 음성 안내(TTS) 및 피드백 DB 자동 적재
🔄
에러 자가 수정 루프 (Self-Correction Loop) :
STEP 04 샌드박스 실행 중 문법/조인 에러나 빈 결과(Empty)가 반환될 경우, 외부 개입 없이 에이전트가 런타임 에러 스택을 스스로 해석하여 STEP 03 코드를 자체 디버깅·재실행함으로써 90% 이상의 정합성을 보장합니다.

3.2 5대 기능 블록 및 인프라 인스턴스 연동 구조

Layer 1 : Client & UI Layer

• KGM 사내 웹 포털 (반응형 대화형 챗 UI)
• 온프렘 음성 모듈 (Voice-to-BOM STT & TTS)
• 계층적 드릴다운 트리 뷰어 (인터랙티브 부품 어셈블리 네비게이터)

Layer 2 : Gateway & Orchestration (컨테이너 CPU 노드)

• API Gateway & Session Manager (사내 SSO 연계)
• Orchestration Controller (ReAct 기반 다단계 에이전트 플래너)
• High-Frequency FAQ Semantic Cache (자주 묻는 질문 0.1초 즉시 응답 캐시)

Layer 3 : Cognitive & Serving (GPU 추론 노드)

• 하드웨어: 고성능 듀얼 GPU 서버 (48GB급 VRAM × 2EA, 총 96GB 이상)
• 서빙 엔진: 캐시 재사용 및 메모리 최적화 기반 초경량 고속 서빙 솔루션
• 탑재 모델: 의미해석 LLM 및 모델 경량화 솔루션 적용 코딩 특화 모델

Layer 4 : Dual Embedded Data Layer (Sandbox)

• 보안 컨테이너 격리 샌드박스 (안전한 코드 실행 환경)
• 임베디드 DB (In-Process 분석형 DB): 수치 집계, 사양 Diff 연산
• 임베디드 그래프 DB (In-Process Graph DB): BOM 다계층 트리 순회, 대체품 경로 탐색
• 제로카피(Zero-Copy) 공유 메모리 파이프라인: 메모리 복사 없는 초고속 결합

Layer 5 : Integration & Continuous RAG (원천 연동)

• KGM 원천 레거시 시스템: 사내 PLM, ERP, BOM 원천 RDB
• 무부하 복제: 읽기 전용 복제본(Read Replica) 및 자동화 CDC 배치 파이프라인
• Active RAG: 최신 출시 차종 정보, 신규 부품 변경점, 피드백 DB

3.3 원천 BOM DB 연동 및 지속적 RAG 현행화 (Continuous RAG)

BOM 데이터는 매주/매월 설계 변경(ECO) 및 연식 변경에 따라 지속적으로 갱신되므로, 운영계 무부하 복제 및 자동 최신화 파이프라인을 구축합니다:

원천 운영계 무부하 동기화 (Read Replica & CDC)

  • 운영계 부하 차단: KGM 운영 DB에 직접 질의하지 않고, 읽기 전용 복제본(Read Replica) 및 컬럼형 스냅샷을 주기적으로(예: 매일 자정 또는 실시간 CDC) 동기화
  • 데이터 전처리 파이프라인: 원천 스키마 정규화, KGM 부품 약어/용어사전 매핑, 결측치 보정을 자동 수행하여 임베디드 DB 및 그래프 인덱스 갱신

빈출 FAQ 캐싱 & 최신 차종 Active RAG 현행화

  • 빈출 질문(FAQ) 시맨틱 캐싱: 자주 묻는 질문-답변 쌍을 메모리 시맨틱 캐시에 저장하여 LLM 재추론 없이 0.1초 내 즉시 응답 반환 (GPU 자원 대폭 절약)
  • 신규 차종·부품 자동 벡터화: 신규 차종 출시나 설계 변경점 발생 시 배치 파이프라인이 메타데이터를 자동 인덱싱하여 RAG 지식베이스를 실시간 최신화

과거 특정 외산 상용 솔루션 단독 종속에서 탈피하여, 쿠버네티스 기반 엔터프라이즈 표준 컨테이너 AI 플랫폼을 기본 아키텍처 출발점으로 채택합니다.

  • 초기 투자 절감: 대규모 초기 하드웨어 구매 없이 사용량 기반 유연한 자원 할당

Model & Serving Innovation

5. 모델 및 서빙 혁신 : 모델 경량화 솔루션 & 초경량 고속 서빙 엔진

5.1 모델 경량화 솔루션 기반 초저지연 경량화 코딩 모델

자동차 BOM 질의는 정확한 코드 생성과 지연 없는 빠른 응답 속도가 핵심입니다. 본 사업에서는 전문 AI 모델 경량화 솔루션을 적용하여, 구조적 프루닝(Pruning), FP8/INT4 정밀 양자화, 도메인 지식 증류를 거친 경량화 코딩 특화 모델을 탑재합니다. 이를 통해 GPU VRAM 사용량을 40~50% 대폭 절감하면서도 95% 이상의 코딩 정합성을 유지하여 동시 접속 처리량을 2배 이상 확대합니다.

5.2 엔터프라이즈 초경량 고속 서빙 솔루션 구성

단일 사용자용 기본 서빙 도구의 동시 요청 처리 한계와 다단계 에이전트 지연을 극복하기 위해 최신 초경량 고속 추론 서빙 엔진을 적용합니다:

에이전트 특화 캐시 재사용 서빙 엔진 (최우선 권장)

• 프리픽스 KV 캐시 재사용 기술로 다단계 에이전트 및 샌드박스 자가수정 루프 실행 시 추론 지연시간 70% 단축
• 초당 토큰 처리량(TPS)을 기존 대비 1.5~2배 향상시켜 복잡한 Coding Agent에 최적

메모리 페이지 최적화 배치 서빙 엔진 (엔터프라이즈 표준)

• 가상 메모리 페이징 기반 최적화로 GPU 메모리 파편화 제로 달성
• 표준 컨테이너 AI 플랫폼과의 네이티브 연동을 통한 운영 안정성 및 오토스케일링 보장

C/C++ 기반 초경량 네이티브 서빙 런타임

• 순수 C/C++ 기반 제로 디펜던시 초경량 바이너리로 극소 메모리 풋프린트 제공
• CPU/GPU 하이브리드 오프로딩 완벽 지원으로 자원 제약 환경에 유연 대응

Hybrid Data Layer

6. 데이터 엔진 혁신 : 임베디드 DB + 임베디드 그래프 DB 듀얼 아키텍처

자동차 BOM 데이터는 단순한 표 형태뿐만 아니라, 부품 간 다계층 구조(모듈 ➔ 서브어셈블리 ➔ 단품)와 부품 공용화/대체 관계 네트워크를 지니고 있습니다. 이에 따라 본 제안은 초고속 분석형 임베디드 DB(수치 집계 및 Diff 연산)에 임베디드 그래프 DB(계층 트리 순회)를 결합한 하이브리드 인메모리 레이어를 구축합니다.

분석형 임베디드 DB (OLAP) 사용 이유

• 임베디드 분석 엔진의 압도적 속도: 수백만 건 부품 테이블을 컬럼 기반 벡터화 연산으로 수 밀리초 내 집계·필터링
• 프로세스 내장형 제로 오버헤드: 별도 DB 서버 데몬 없이 샌드박스 런타임 메모리 내에서 직접 구동
• 공유 메모리 Zero-Copy 통합: 데이터프레임과 메모리 복사 없이 연동되어 사양 간 차이점(Diff) 계산에 최적

임베디드 그래프 DB (Graph DB) 채택 이유

• 초경량 인프로세스 그래프 엔진: 무거운 외부 분산 그래프 서버 없이 샌드박스 프로세스 내에 직접 내장
• BOM 계층 트리 초고속 순회: 그래프 쿼리로 모듈-어셈블리-단품 간 다계층 트리를 밀리초 내 순회 탐색
• 부품 종속성 & 대체 경로 식별: 특정 부품의 상위 차종 역추적 및 단종 부품의 호환 대체 경로 즉각 식별

듀얼 임베디드 엔진 결합 시너지

• 고속 공유 메모리 파이프라인: 임베디드 그래프 DB의 순회 결과와 분석형 임베디드 DB의 수치 테이블을 단일 프로세스에서 제로카피로 결합
• 기존 원천 데이터 직접 연계: 컬럼형 스냅샷, CSV, RDB 복제본 등 기존 KGM 시스템 데이터를 별도 무거운 ETL 없이 직접 질의

Interactive Interface

7. 인터페이스 혁신 : 음성 검색(Voice-to-BOM) & 계층적 드릴다운 트리 UI

과거의 단순 텍스트 챗봇 API를 넘어, 연구원과 현장 실무자가 직관적으로 BOM을 탐색할 수 있는 차세대 멀티모달 인터랙티브 UI를 구축합니다.

🎤 음성 검색 : Voice-to-BOM (온프렘 음성인식 STT)

  • 핸즈프리 현장 질의: 연구소 실험실이나 공장에서 장갑을 끼고 작업 중에도 마이크 음성으로 즉각 부품 조회
  • 사내망 보안 음성 인식: 외부 클라우드 전송 없이 사내 GPU 서버 내 경량 음성인식 모델로 실시간 한국어·부품 약어 변환
  • 복합 멀티모달 응답: 음성 질의에 대해 음성 요약 안내와 함께 부품 비교표 및 다운로드 화면 동시 제공

🌳 계층적 드릴다운 트리 인터페이스

  • 시각적 계층 트리 네비게이터: 완성차 ➔ 시스템 ➔ 모듈 ➔ 서브어셈블리 ➔ 단품 파트로 이어지는 계층 구조 시각화
  • 챗봇 답변과 트리 뷰 양방향 연동: 챗봇이 상위 모듈을 답변하면 트리 뷰에서 해당 위치가 자동 하이라이트 및 확장
  • 마우스 클릭 & 자연어 혼합 탐색: 원하는 모듈을 클릭하여 하위 부품을 드릴다운하거나, 반대로 단품을 선택하여 상위 차종 역추적

11. 성공적인 사업 착수를 위한 사전 협의 요청 사항

본 사업의 신속하고 성공적인 론칭을 위해 KG ICT와 다음 3가지 사항에 대한 사전 협의를 요청드립니다.

1. 배포 환경 결정 (On-Prem vs Cloud)

KG ICT 전산실 내 GPU 인프라 가용 여부 및 클라우드 활용 정책을 확인하여 Option A (사내 전용 GPU 서버 신규 도입) 또는 Option B (기보유 인프라/클라우드 활용 SW 구축) 방향을 확정하고자 합니다.

2. 상호 데이터 준비 (Data Readiness) 워크숍

1차 대상 주력 차종(토레스, 렉스턴, 액티언 등 3~4개 차종)의 원천 BOM 테이블 스키마, 부품 계층 구조 정의서, 현업 약어/용어사전 샘플 데이터를 조기 상호 검토하여 정제 리드타임을 단축하고자 합니다.

3. 현업 대표 질문 셋 (Golden Test Set) 수집

R&D 연구소 및 원가기획 부서에서 가장 빈번하게 요청하는 대표 BOM 조회 및 사양 비교 질문 30~50건을 사전에 공유해 주시면, 초기 에이전트 정확도 벤치마크 기준으로 즉시 반영하겠습니다.

BOM Bill of Materials (부품 구성표) 자동차 한 대를 제작하기 위해 필요한 모든 부품, 모듈, 어셈블리의 품번, 명칭, 수량, 계층 구조 및 조립 관계를 정의한 데이터베이스.
EBOM / MBOM Engineering BOM / Manufacturing BOM EBOM: 연구소 설계 관점의 부품 구조표 / MBOM: 생산 공장 및 조립 라인 관점의 공정 중심 부품표.
표준 컨테이너 AI 플랫폼 Enterprise Container AI Platform 쿠버네티스 기반의 엔터프라이즈 오픈 AI 플랫폼. 온프레미스와 퍼블릭 클라우드 간 애플리케이션 일관성과 확장성을 보장하는 핵심 기반 스택.
모델 경량화 솔루션 AI Model Compression Solution 구조적 프루닝, 정밀 양자화, 지식 증류를 통해 거대 코딩 모델을 손실 없이 경량화하여 서빙 속도와 동시 처리량을 극대화하는 기술.
초경량 고속 서빙 엔진 High-Speed LLM Serving Engine 프리픽스 캐시 재사용 및 메모리 페이지 최적화를 통해 다단계 에이전트 및 자가수정 루프 지연시간을 70% 단축하는 고성능 추론 서빙 엔진.
분석형 임베디드 DB In-Process Analytical Embedded DB 별도 서버 없이 프로세스 내(In-Process) 직접 구동되는 초고속 컬럼 지향 분석형 DB. 수백만 건 부품 데이터를 수 밀리초 내 집계·Diff 연산.
임베디드 그래프 DB In-Process Embedded Graph DB 별도 분산 서버 없이 샌드박스 프로세스 내에 직접 내장되는 초경량 그래프 DB. BOM 계층 트리 순회 및 부품 종속성·대체 경로 탐색에 최적화.
Voice-to-BOM 온프렘 음성 검색 인터페이스 연구원/현장 실무자가 마이크 음성 질의 시 온프레미스 음성인식(STT) 모델을 통해 핸즈프리로 즉각 부품 검색을 수행하는 멀티모달 기능.
Drill-down Tree UI 계층적 드릴다운 트리 UI 완성차부터 단품 부품까지 이어지는 BOM 계층 트리를 시각적으로 펼쳐가며 대화와 클릭을 결합하여 직관적으로 탐색하는 인터페이스.
Code-Interpreter Agent Sandbox Coding Agent 사용자의 자연어 질문을 해결하기 위해 경량화 코딩 모델이 분석 코드 및 임베디드 DB 쿼리를 직접 작성하고 격리된 환경에서 실행하여 결과를 도출하는 에이전트.
Self-Correction Loop 자가 수정 루프 생성된 코드가 런타임 에러나 빈 결과(Empty)를 반환할 때, 에이전트가 에러 스택을 스스로 해석하고 코드를 재작성하여 실행함으로써 정합성을 90%+로 끌어올리는 메커니즘.
Text-to-SQL Text-to-SQL 자연어 질의를 SQL 문장으로 일회성 변환하는 전통적 방식. 복잡한 다중 조인 및 계층 트리 구조에서 문법 오류와 취약성이 높음.
ReAct 패턴 Reasoning + Acting 에이전트가 생각(Reasoning), 도구 실행(Acting), 결과 관찰(Observation)을 반복하여 복합 문제를 자율 해결하는 에이전트 설계 패러다임.
경량화 코딩 특화 모델 Lightweight Coding Specialist LLM 복잡한 알고리즘, 테이블 조인 및 데이터 분석 코드 작성 능력이 뛰어나며 사내 GPU 서버에 최적화된 오픈소스 기반 코딩 특화 모델.
양자화 (Quantization) INT4 / FP8 Quantization 16비트 모델 가중치를 4/8비트로 정밀 압축하여 정확도 손실 없이 GPU VRAM 사용량을 대폭 절감하고 추론 속도를 2배 이상 향상시키는 기술.
격리 샌드박스 Isolated Container Sandbox 에이전트가 생성한 분석 코드가 시스템에 위해를 가하지 못하도록 네트워크와 시스템 자원이 안전하게 격리된 컨테이너 실행 런타임.
Diff Analyzer 사양 간 차이 분석기 토레스 가솔린 vs 하이브리드 등 복수 차종/트림 간 적용 부품의 차이점, 변경된 파트넘버, 사양 변경 내역을 자동으로 비교 연산하여 표로 제공하는 기능.
Ad-hoc Query 비정형 임시 질의 정형화된 보고서 화면 외에 현업 실무자가 특정 목적을 위해 IT 부서에 수시로 요청하는 임시 데이터 추출 작업.
Data Readiness 상호 데이터 준비성 AI 구축 착수 전 고객사(KGM/KG ICT)와 제안사 간의 원천 BOM 스키마 정의, 부품 코드 표준화, 결측치 및 테이블 정제를 수행하는 선행 작업 단계.
